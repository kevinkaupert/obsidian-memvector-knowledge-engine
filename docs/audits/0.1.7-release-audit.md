# Release Audit 0.1.7 — Claims vs. Implementation

> **Scope:** every commit in `0.1.6..0.1.7` (13 commits, `3dd2442` … `d1d4387`)
> **Audited:** 2026-09-28
> **Question asked:** did each commit actually do what it claimed, and does the release hide
> architectural defects?
> **Outcome:** all findings below were fixed inside 0.1.7 and the release was rebuilt. This
> document is kept as the record of what was wrong and why, so the same classes of defect are
> recognizable next time. Test suite after the fixes: **413 tests in 46 files** (from 375 in 43).

## Findings

### F1 — Silent layout regression on upgrade; re-broke #68 · *high*

`loadRelationVocabulary` returned the vault's `wiki/relation-types.json` terms verbatim with no
merge against the bundled defaults. Every vault seeded before 0.1.7 has that file *without*
`weight`/`repels` — the fields did not exist yet — so `computeGraphTopologyWeights` fell through to
`def?.weight ?? 1.0`. No migration existed anywhere (`migrateSettings` only covers `data.json`).

Verified empirically against a legacy-vocabulary fixture:

```
CONFLICTS_WITH   repel set empty, conn = 1.0   (attracts instead of repelling)
INDEPENDENT_OF   conn = 1.0  (instead of BASELINE_WEIGHT 0.05)
EQUIVALENT_TO    conn = 1.0  (instead of 1.3)
label absent from the active preset → conn = 1.0
```

`INDEPENDENT_OF` going from `0.05` to `1.0` is exactly the bug 0.1.5 fixed under #68. ADR-0002
asserted "Existing vaults keep identical layout behavior", which only held for vaults *without* a
vocabulary file. The same mechanism hit a preset switch: after moving to Law/Medicine, all STEM-era
edges attracted at `1.0`, and `activatePreset`'s docstring ("No re-embedding needed — edge labels
are stored as strings") papered over that semantic loss.

**Fixed:** `relationVocabulary/layoutDefaults.ts` fills `weight`/`repels` from the bundled label
defaults for any term carrying neither, and `computeGraphTopologyWeights` resolves an unknown label
against the bundled set. Explicit values — including `repels: false` — still win. 11 new tests.

### F2 — Controls moved into Settings stopped working live · *medium*

`92022f7` removed Visual style, Show relation notes and Agent guidelines from the toolbar. The old
toolbar handlers called `ctx.redraw()` / `ctx.setShowRelationNotes()`. The replacement Settings
controls only called `host.saveSettings()`, and `MemVectorPlugin.saveSettings()` is a bare
`saveData`. `showRelationNotes` is read by the view in `onOpen` only. Net effect: visual style and
relation-note visibility took effect only after closing and reopening the 2D view.

**Fixed:** `SettingsHost.applySettingsToOpenViews({ relayout? })` →
`MemVectorPlugin.applySettingsToOpenViews` → `VectorScatterView.applyExternalSettingsChange`.
Wired into the style dropdown, the relation-notes toggle, the label-opacity slider, and every
relation-vocabulary mutation (which passes `relayout: true`, because changed weights move nodes).

### F3 — Lasso toggle removed without replacement; dead state · *medium*

The `t.lblLasso` toggle disappeared in `92022f7` and was not replaced, leaving
`ctx.lassoSelectMode` permanently `false`. Lasso remained reachable only through the
`|| e.shiftKey` branch. Neither the commit message nor the release notes mentioned it, and
`docs/ARCHITECTURE.md` still documented the toggle.

**Resolution (as decided):** the toggle stays removed; `Shift` + drag is the documented gesture.
`ARCHITECTURE.md`, `USER_GUIDE.md` and `README.md` now say so, the release notes carry it as an
upgrade note, and the orphaned keys are gone (see F7).

### F4 — Two defects in the rAF throttle (PR #130) · *medium*

- `canvasInteraction.ts` used the bare global `requestAnimationFrame` instead of
  `window.requestAnimationFrame`. ESLint flagged it explicitly
  (`obsidianmd/prefer-window-timers`, "for popout window compatibility") and the rest of the
  codebase already did it right. In an Obsidian popout window the main window's rAF does not fire
  reliably, so the canvas freezes during pan/zoom.
- The teardown returned by `wireCanvasInteraction` removed the listeners but never cancelled the
  pending frame, so a scheduled redraw could fire against a detached canvas after `onClose`. The
  same pattern is carefully cancelled for `searchAnimHandle`. Before PR #130 `ctx.redraw()` was
  synchronous and this window did not exist — it was a regression against the 0.1.6 leak fix.

**Fixed:** both. `cancelAnimationFrame` calls in the view were also scoped to `window`, and the
lint rule is now an **error** so this cannot ship as a warning again (see F5).

### F5 — CI could not detect bundle drift · *medium, architectural*

`.github/workflows/ci.yml` ran `npm run build` but never compared the result against the committed
`main.js`. Consequence: `f3609b0`, `75aacfe` and `39b1033` changed `src/` without rebuilding and
needed the manual catch-up commit `e38e8c6` ("chore: rebuild main.js"). Since `main.js` *is* the
shipped artifact, `main` carried a bundle that did not match its source for three commits.
`npm run lint` also had no `--max-warnings` gate, which is how F4's warning passed CI.

**Fixed:** a `git diff --exit-code -- main.js` step after the build, and
`obsidianmd/prefer-window-timers` promoted to `error`. Of the remaining 12 warnings, 10 were
`ui/sentence-case` on model names and URLs, 1 an unused variable
(`src/relationVocabulary/persistCustomType.ts`) and 1 a `Vault.trash` call instead of
`FileManager.trashFile` (`src/relationVocabulary/presets.ts`); the last two were fixed in #147.
A blanket `--max-warnings 0` would be noise on the sentence-case warnings; the targeted rule is
the one that had teeth.

### F6 — "Complete localization" did not hold · *medium-low*

Hardcoded strings remained where translation keys already existed:

- `synthesis.ts` — `"[INFO] Suche verwandten Kontext (…)"`, German regardless of
  `settings.language`, while `t.lblHopSingle`/`lblHopPlural` existed.
- `contextPreview.ts` — `"Hop"`/`"Hops"`.
- `synthesis.ts` — `"> [!note]- Gedankengang des Modells"`, German in the synthesis output.

**Fixed:** new keys `synthSearchingContext` and `synthThinkingBlockTitle`; `buildPreviewEntries`
takes injected hop wording (defaulted, and covered by a test that asserts the injected values are
used).

### F7 — Duplicated source of truth for the relations prompt header · *medium-low*

`e993484` added `synthRelHeading` and `synthRelReasonLabel` to all three i18n files, but
`buildRelationEdgesSection` hardcoded the same strings inline behind a `lang === "de"` ternary.
Both keys were orphaned from birth — which is precisely why `d1d4387` had to change the Memgraph
wording in **two** places. An orphan scan over all 246 keys found 16 unused, 5 of them new in this
release (`lblLasso`, `lblShowEdges`, `lblVisualStyle`, `synthRelHeading`, `synthRelReasonLabel`).
0.1.4 had already booked "clean orphaned translation keys" (#38, #49) as done.

**Fixed:** the inline copies are gone (`getTranslation(lang)` is the only source) and the three
toolbar orphans were deleted. The 11 pre-existing orphans (`cloudNaming*`, `linkMode*`,
`relDelete*`) belong to unshipped features and were left alone deliberately.

### F8 — `labelPlacement.ts`: untested, docstring ≠ code, O(n²) per frame · *low-medium*

The release's only new module had no test file (against 43 existing ones). Its docstring claimed
"Rects are added in priority order (clusters, then active/focused nodes, then the rest)", but
`drawNodes` ran a single pass in array order: active nodes passed `force=true` and therefore always
drew, but *on top of* an already-placed unselected label — leaving the overlap exactly where it
hurts most. `tryPlaceLabel` was also a linear scan over all placed rects, i.e. quadratic in the
number of drawn labels, now evaluated once per animation frame during pan/zoom.

**Fixed:** `createLabelPlacer()` buckets reservations in a uniform 96px screen-space grid, and
`drawNodes` collects label candidates during the dot pass and places them in two real priority
rounds. 17 new tests (8 for the placer including a 5,000-rect scaling case, 9 for `drawNodes`
covering the priority behavior the docstring promised).

### F9 — Context preview rows could overflow the panel · *low*

`.memvector-context-preview-name` had `flex: 1 1 auto; overflow: hidden; text-overflow: ellipsis`
but no `min-width: 0`. A flex item's automatic minimum size is its content size, so a long note
title did not ellipsize — it pushed the meta column and the dismiss button out of the 280px panel.

**Fixed:** `min-width: 0` added. The redundant `margin-left: auto` on the dismiss button was
removed with a comment explaining why it is unnecessary.

### F10 — Remaining legacy graph-backend wording · *low*

`d1d4387` fixed the prompt headers but left `docs/ARCHITECTURE.md` describing current behavior as
"typed Memgraph relation edges" and "connected … via WikiLink and/or Memgraph relation", plus
`RelationTally.memgraph` and several comments in `relatedNodes.ts` / `drawNodes.ts`. The hits in
`GRAPHRAG.md` and `TESTING.md` are inside sections explicitly marked historical or
"not implemented yet" and are legitimate.

**Fixed:** docs updated and `RelationTally.memgraph` renamed to `typed`. `memgraphPassword` in
`secrets.ts` is a persisted legacy `data.json` key and was deliberately left untouched.

### F11 — Smaller claim/implementation gaps · *low*

- **Release notes** cited `--[CONTRADICTS]-->`; no such label exists (canonical `CONFLICTS_WITH`;
  the `relContradicts` key was removed in this very release). They also cited `maxNeighbors * 3`,
  which was never the removed expression (`perHop * 3 + selected.length`). Both corrected.
- **Relation Type Manager** displayed `weight`/`repels` read-only, while ADR-0002 promised tuning
  "using the Settings UI". The only route was delete + re-add, which loses `reversed`, `term` and
  `category`. Now editable in place, with validation on the weight field (previously a
  non-numeric entry silently became `1.0`).
- **Dead code:** `withoutDismissed` was a no-op — `enrichContext` already filtered the same ids —
  and `buildEnrichedSection` computed a `linkLines` string no caller consumed. Both removed.
- The preview's reset button visibility was only set inside the `try`, so a failed enrichment left
  the dismissed set unreachable. Now set before the fetch.
- **README badges** read `version-0.1.6` and `tests-257`. 0.1.5 had already booked badge updates
  (#67) as done. Corrected.
- Non-finite similarity guard (`Number.isFinite(hit.score)`) and the `isRelationNode` path fix both
  rode along in a commit declared `chore(i18n)` (`680a2a6`). They are real bugfixes and are now
  listed in the changelog.
- The 0.1.7 version bump sat inside a fix commit (`30059df`); 0.1.6 still had a dedicated
  `chore(release)` commit for it.

## Undocumented changes now in the changelog

The original 0.1.7 changelog and release notes omitted, among others: the removal of five toolbar
controls and their move into Settings; the default flips `showEdges false→true` and
`showRelationNotes true→false`; the new Settings section and its reordering; the vocabulary being
slimmed from 37 synonym entries to 13 (dropping the `buildConversationalCategories` scaffolding
that the 0.1.5 changelog had listed as a planned #43 expansion); the bidirectional live-save fix
#120; and the two bugfixes hidden in `680a2a6`.

## Process takeaways

1. **A committed build artifact needs a CI freshness gate.** Without it, "the tests are green"
   says nothing about what users install.
2. **Introducing an optional field with semantics is a migration.** Data written before the field
   existed reads as "unset", and "unset" must mean the old behavior, not the type default.
3. **A lint warning that CI does not fail on will ship.** If a rule is worth having, it is an error.
4. **Adding an i18n key and inlining the same string is worse than not adding the key.** Every
   later edit has to find both, and only one of them is what users see.
5. **A commit prefixed `chore:` should not contain bugfixes.** They vanish from the changelog and
   from anyone's mental model of what shipped.
6. **"Moved to Settings" is not a refactor.** The wiring a control had — a redraw, a re-layout —
   has to move with it.
